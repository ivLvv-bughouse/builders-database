# Строительная компания — БД

Курсовая работа по дисциплине «Базы данных», 3 курс ГУАП, 6 семестр.

Тонкий клиент на Python + tkinter, база данных PostgreSQL в Docker.

---

## Стек

| Компонент | Технология |
|---|---|
| GUI | Python 3.11, tkinter + ttk |
| БД | PostgreSQL 16 (Docker) |
| Драйвер | psycopg2-binary |
| Конфиг | python-dotenv |

## Быстрый старт

### 1. Требования

- [Python 3.11+](https://www.python.org/downloads/)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/)
- Git (опционально)

### 2. Клонировать / скачать репозиторий

```bash
git clone <url>
cd builders-database
```

### 3. Запустить PostgreSQL

```bash
docker-compose up -d
```

Docker автоматически:
- Поднимет PostgreSQL 16 на порту `5432`
- Создаст базу `construction_db`
- Применит схему (`01_schema.sql`) и тестовые данные (`02_seed.sql`)

Проверить, что контейнер запустился:

```bash
docker ps
```

Должна быть строка с именем `construction_db` и статусом `Up`.

### 4. Создать файл окружения

```bash
# Windows (PowerShell)
Copy-Item .env.example .env

# Linux / macOS
cp .env.example .env
```

Файл `.env` уже настроен под docker-compose и не требует правок:

```
DB_HOST=localhost
DB_PORT=5432
DB_NAME=construction_db
DB_USER=postgres
DB_PASSWORD=postgres
```

### 5. Установить зависимости Python

```bash
pip install -r requirements.txt
```

### 6. Запустить приложение

```bash
python main.py
```

В терминале появится:

```
DB connected successfully
```

После этого откроется главное окно приложения.

## Работа с приложением

### Вкладки 1–5 (Клиенты / Сотрудники / Здания / Объекты / Договоры)

Каждая вкладка устроена одинаково:

| Кнопка | Действие |
|---|---|
| **Обновить** | Перечитать данные из БД |
| **Добавить** | Открыть форму создания новой записи |
| **Редактировать** | Открыть форму с данными выбранной строки |
| **Удалить** | Удалить выбранную строку (с подтверждением) |

Поля с фиксированными значениями (тип клиента, статус объекта и т.д.) выбираются из выпадающего списка — ввести некорректное значение невозможно.

### Вкладка «Отчёты»

**Договор купли-продажи** — введите номер договора, нажмите «Сформировать». Отображает: ФИО клиента, тип объекта, площадь, цену, дату и статус.

**Реестр сделок по сотрудникам** — введите диапазон дат в формате `ГГГГ-ММ-ДД` (например `2024-01-01` / `2025-12-31`), нажмите «Сформировать». Показывает все сделки с разбивкой по менеджерам.

**Выручка по типам объектов** — тот же диапазон дат. Показывает количество сделок и общую выручку по каждому типу объекта.

## Управление Docker

```bash
# Остановить контейнер (данные сохранятся в volume pgdata)
docker-compose stop

# Запустить снова
docker-compose start

# Полный сброс (удалить контейнер И данные)
docker-compose down -v
```

После `down -v` при следующем `up -d` схема и сид применятся заново автоматически.

## pgAdmin (опционально)

В `docker-compose.yml` есть закомментированный блок сервиса pgAdmin.
Раскомментируйте его, пересоберите стек и откройте `http://localhost:8080`.

Логин: `admin@admin.com` / пароль: `admin`.

При добавлении сервера укажите хост `db` (имя сервиса внутри Docker-сети), порт `5432`.

## Архитектура (для защиты)

```
main.py
  └── test_connection()        проверка БД при старте
  └── MainWindow               GUI-приложение
        └── *Tab               по одной вкладке на сущность
              └── *Repository  CRUD через psycopg2
                    └── *      модели-датаклассы

reports/report_generator.py   аналитика (JOIN-запросы)
```

**Ключевые принципы:**

- **Паттерн «Репозиторий»** — весь SQL только в `repositories/`, UI не знает о psycopg2.
- **Параметризованные запросы** (`%s`) — защита от SQL-инъекций, никаких f-строк с пользовательскими данными.
- **Синглтон-соединение** — одно `psycopg2.connect()` на всё время работы приложения.
- **AppError** — единый тип исключения для всех слоёв; UI ловит только его.
- **`from_row(cls, row)`** — гидратация модели из кортежа psycopg2 без дублирования индексов.
